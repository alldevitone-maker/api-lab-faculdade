# Building with AI in Public

## Week 4 | September 2026

### The roadmap that was never planned

I did not start with a master architecture.

I started with a problem.

Then another problem appeared.

Then another.

What began as a few conversations with an LLM gradually became a practical system for working with context, tools, files, APIs, automation, versioning and knowledge.

This page documents that evolution in public.

## What I was trying to solve

The original goal was simple: use AI to solve real problems faster without losing control of the work.

That quickly exposed a harder question.

How do you keep the context useful, the sources traceable, the changes reproducible and the final decisions human controlled?

## What actually happened

The work grew through a sequence of practical layers:

1. Real problems
2. Human orchestration
3. Conversations and context
4. Termux and Python
5. APIs and authentication
6. Classroom and Drive workflows
7. Audit and versioning
8. Obsidian as a knowledge base

None of these layers were added because they looked interesting on a roadmap.

They appeared because the previous layer created a new problem.

## What changed this weekend

The focus moved beyond simply asking an AI for answers.

The work became more about:

* context management
* source traceability
* versioning
* governance
* automation
* knowledge architecture
* separating public, academic and private material
* deciding which actions should remain under human control

That change matters because isolated AI interactions are useful, but systems become much more valuable when the context, evidence and decisions can survive beyond one conversation.

## One visible artifact

The API Lab is one public artifact created during this process:

https://github.com/alldevitone-maker/api-lab-faculdade

It is a learning focused environment for understanding HTTP APIs through interactive examples and simulations.

It is not the entire roadmap.

It is one concrete output from it.

## Next

The next layer is becoming clearer:

* Agents
* MCP
* RAG
* Observability

The objective is not to collect more tools.

The objective is to understand how these pieces can form a coherent, auditable system.

## Principle

> I did not plan this roadmap. Problems created it.

This document will evolve as the work evolves.
