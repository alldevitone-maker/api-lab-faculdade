1. Fundamentos

A mesma URL pode aceitar ações diferentes. O servidor observa o método e o caminho. 

GET    /usuarios
POST   /usuarios
GET    /usuarios/42
PATCH  /usuarios/42
DELETE /usuarios/42
GET

Ler

GET /usuarios

Solicita uma representação do recurso. Em uso normal, GET não deve alterar o estado do servidor.

POST

Criar ou processar

POST /usuarios

{
  "nome":"Humano"
}

Envia conteúdo para processamento. Muitas APIs usam POST para criação.

PUT e PATCH

Atualizar

PUT   /usuarios/42
PATCH /usuarios/42

PUT e PATCH não são sinônimos.

DELETE

Excluir

DELETE /usuarios/42

Solicita a remoção da associação atual do recurso.

HEAD

Metadados

HEAD /usuarios/42

É equivalente ao GET em semântica, mas a resposta não inclui o conteúdo da representação.

OPTIONS

Opções

OPTIONS /usuarios

Consulta opções de comunicação disponíveis para o recurso ou servidor.

3. Onde isso entra em Xano + FlutterFlow?

O Xano funciona como backend. O FlutterFlow funciona como cliente visual que dispara as chamadas e usa a resposta.

Tela FlutterFlow
Botão, formulário, lista
API Call
Método, URL, headers, params, body
Endpoint Xano
GET /alunos, POST /alunos
Banco e lógica
Consulta, validação, criação
JSON de volta
FlutterFlow usa os dados na interface

11. Autoteste e auditoria

O autoteste percorre combinações de método, formato, body, query params, ID, autenticação e header customizado.

Autoteste ainda não executado nesta sessão.
Validação: URL, recurso, ID, JSON, query, token e header.
HTTP: GET, POST, PUT, PATCH, DELETE, HEAD e OPTIONS.
Saídas: HTTP, cURL e fetch.
Fetch: aceita resposta vazia e resposta não JSON sem quebrar o exemplo.
Autenticação: Bearer token normalizado.
UX: campos inválidos recebem destaque e mensagem específica.
Simulação local: consulta, filtro, paginação, criação, substituição, atualização parcial, exclusão e recursos ausentes.
